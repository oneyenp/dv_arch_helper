# 模块交互关系 WebUI（二期）设计与实施计划

## 1. 总结

构建单用户、本地部署的模块交互分析工作台，读取一期生成的 `InteractionModel` JSON，不在 WebUI 中启动 NPI 抽取。

默认进入模块关系总览，支持大规模关系浏览、接口组下钻、CDC/诊断筛选、手动分组和筛选结果导出。默认中文，可切换英文；内部 API、枚举和信号名称始终使用英文。

## 2. UI 与交互

- 工作台包含 `模块总览`、`关系表`、`诊断`、`分组编辑` 四个视图；选择与筛选状态跨视图保留并同步到 URL。
- 模块总览采用方向分栏：
  - 上游模块在左，DUT 固定居中，下游模块在右。
  - 同时存在输入、输出或 `inout` 的模块位于下方双向区域。
  - 接口组显示 `←/→/↔`、关系数量、时钟关系和异常状态。
- 模块卡片使用虚拟列表；仅为当前选中的模块或接口组绘制局部关系图。
- 点击接口组打开右侧详情抽屉，按输入、输出、`inout` 展示端口映射、时钟域、追踪摘要和诊断，并提供复制 scope、端口及路径。
- 关系表默认采用“接口组父行 → 关系子行”，可切换为扁平视图；支持服务端过滤、排序、分页、固定列和当前结果导出。
- 分组编辑使用独立的 DUT 端口工作区，每个端口只出现一次。编辑自动分组时，先复制成完整手动草稿，再支持批量赋组、解除分组、改名、撤销/重做和未分组筛选。
- 分组草稿支持：
  - 显式保存到启动时指定的配置文件。
  - 下载为新的配置文件。
  - 未保存时刷新、重载或关闭页面必须确认。
- 默认采用浅色高密度主题；CDC、unknown、选中和错误状态均使用文字/图标与颜色共同表达。
- 使用翻译键实现 `zh-CN` 与 `en-US` 切换，默认 `zh-CN`；缺失翻译回退英文。

## 3. 技术架构

- 后端采用 FastAPI，启动时校验一期 JSON，并在内存中建立端口、接口组、模块、方向、时钟域和诊断索引，不引入数据库。
- 前端采用 React、TypeScript、Vite、TanStack Table/Virtual、TanStack Query、React Flow 和 react-i18next。
- 生产构建由 FastAPI 提供静态资源，运行时不需要 Node。
- 关系数据采用服务端筛选、排序和分页；前端只虚拟化当前已取回的行。
- React Flow 只渲染当前选择的局部关系，避免将完整设计绘制成大图。

技术选型参考：

- [TanStack Table Virtualization](https://tanstack.com/table/latest/docs/framework/react/guide/virtualization)
- [TanStack Table Expanding](https://tanstack.com/table/latest/docs/framework/react/guide/expanding)
- [React Flow Performance](https://reactflow.dev/learn/advanced-use/performance)
- [react-i18next](https://react.i18next.com/latest)

## 4. 启动接口

```bash
python -m dv_arch_helper.web \
  --report interactions.json \
  --group-config groups.json \
  --host 127.0.0.1 \
  --port 18080
```

启动参数语义：

- `--report`：必需，只读的一期规范 JSON。
- `--group-config`：可选；提供且可写时允许覆盖保存，否则只允许下载分组配置。
- `--host`：默认 `127.0.0.1`。
- `--port`：默认 `18080`，避免与常见本地开发服务的 `8000` 端口冲突。
- `--access-token`：监听非 loopback 地址时必需。

## 5. REST API

- `GET /api/v1/report`：返回报告元数据、schema、能力和统计。
- `GET /api/v1/overview`：返回方向分栏的模块与接口组汇总。
- `GET /api/v1/interface-groups`：查询接口组和聚合计数。
- `GET /api/v1/relations`：按组、模块、方向、时钟、状态和搜索词进行分页过滤及排序。
- `GET /api/v1/diagnostics`：分页查询诊断。
- `GET /api/v1/ports`：返回分组编辑所需的唯一 DUT 端口。
- `POST /api/v1/grouping/draft`：将当前自动结果复制为完整手动草稿。
- `POST /api/v1/grouping/preview`：校验草稿并返回重算后的组级汇总，不写盘。
- `PUT /api/v1/group-config`：使用 revision/`If-Match` 防止覆盖旧版本，并原子保存配置。
- `POST /api/v1/reload`：重新读取相同报告和配置，成功后原子替换内存快照。
- `POST /api/v1/exports/relations`：按当前筛选导出 CSV/XLSX。
- 提供完整 JSON 和手动分组配置的下载接口。

分组配置只覆盖运行时的接口组视图，不修改一期原始报告。

## 6. 双向交互规则

- 相对于 DUT，只有输入关系的接口组标记为 `inbound`，显示为 `上游 → DUT`。
- 只有输出关系的接口组标记为 `outbound`，显示为 `DUT → 下游`。
- 同一接口组包含输入与输出，或包含 `inout` 时标记为 `bidirectional`，显示 `↔`。
- 同一对端模块拥有不同方向的多个接口组时，模块进入双向区域，但每个接口组仍保留自身实际方向。
- 右侧详情抽屉将双向接口拆分为输入、输出、`inout` 三个区块。
- 时钟关系按每个方向分别计算，不把整个双向接口压缩为单一 CDC 状态。

## 7. 安全和异常处理

- 默认只监听 `127.0.0.1`；远程使用推荐 SSH 端口转发。
- 监听非 loopback 地址时必须提供访问 token。
- 不提供服务端目录浏览、任意路径写入、报告上传或 WebUI 内启动 NPI。
- 首次报告加载失败时显示阻断页，区分文件不存在、JSON/schema 无效、版本不兼容和权限问题。
- 单条数据异常不阻断工作台，保留其余内容并进入诊断。
- 重新载入期间继续提供旧快照；新报告校验或索引失败时继续保留旧数据。
- 配置 revision 冲突返回 `409`，不自动覆盖；用户可重新载入或下载当前草稿。
- 保存、重新载入和导出均显示进行中、成功或失败状态。

## 8. 性能目标

规模基线为 50 个并行模块、10,000 个 DUT 端口和最多 30,000 条关系。

- 后端载入与索引不超过 5 秒。
- 后端峰值额外内存不超过 500MB。
- 常用过滤和排序 API 的本机 p95 不超过 300ms。
- 首屏可交互时间不超过 3 秒。
- 表格只挂载可见行与少量 overscan，不创建全量 DOM。
- 局部关系图最多渲染 200 条边；超过时显示总数并要求继续筛选，关系表仍可访问全部数据。
- 图节点与边使用固定、轻量组件，不使用持续动画。

## 9. 测试与验收

### 后端测试

- schema 校验和版本不兼容处理。
- 内存索引和全部过滤组合。
- 分页、排序和稳定结果顺序。
- 上游、下游及双向分类。
- 分组草稿、预览和配置校验。
- revision 冲突和原子保存。
- 成功及失败的原子重新载入。
- CSV/XLSX 导出与当前过滤条件一致。
- 非 loopback 地址的访问 token 校验。

### 前端测试

- 四视图之间的选择和筛选状态同步。
- URL 状态恢复。
- 模块总览、右侧详情抽屉和局部关系图。
- 接口组父行及关系子行展开。
- 自动分组转手动草稿。
- 批量赋组、解除分组、改名、撤销/重做。
- 未保存草稿离开确认。
- `zh-CN/en-US` 切换、英文回退和翻译键完整性。

### 端到端与性能测试

- Playwright 覆盖打开报告、CDC 筛选、总览下钻、自动转手动、保存、另存为、语言切换和筛选结果导出。
- 使用固定 10k/30k 夹具验证后端预算、虚拟滚动和浏览器内存。
- 局部图分别测试 1、200 和超过 200 条边的行为。

验收要求：

- 上游、下游和双向关系分类准确。
- 总览、关系表和诊断计数一致。
- 手动分组不会修改原始报告。
- 中英文界面功能一致且翻译键完整。
- CSV/XLSX 内容与当前筛选条件一致。

## 10. 实施顺序

1. 建立 FastAPI 服务入口、配置解析、schema 校验和内存快照。
2. 实现报告索引、总览、关系、端口及诊断查询 API。
3. 搭建 React/Vite/TypeScript 前端、路由、URL 状态和 i18n。
4. 实现模块总览、双向区域、详情抽屉和局部关系图。
5. 实现虚拟化关系表和诊断视图。
6. 实现分组草稿、预览、撤销/重做、原子保存和下载。
7. 实现筛选结果 CSV/XLSX 导出与完整报告下载。
8. 完成访问 token、异常页、重载和并发 revision 保护。
9. 完成单元、集成、Playwright、i18n 和 10k/30k 性能测试。
10. 以生产构建由 FastAPI 静态托管的方式完成单机交付。

## 11. 明确边界

- 本期只分析启动时指定的一份既有报告，不管理多工程、历史报告或报告对比。
- 本期不在 WebUI 中执行 NPI、浏览服务器文件系统或直接控制 Verdi。
- 仅提供 Verdi 定位信息复制；自动启动和控制 Verdi 留到下一期。
- 不建设账号、多人协作、中心数据库或权限系统。
